# Analytics contracts

|Metric|Definition|
|---|---|
|Processed volume|Sum of EUR amounts for successful, recovered and refunded payments; gross settled, not net revenue|
|Payment success|Successful + recovered + refunded count divided by all non-pending payments|
|Failed value|EUR value of payments whose final status is failed|
|Recovered value|EUR value of recovered payments, counted once|
|Retry success|Successful attempts divided by payments reaching that attempt; first-attempt pending outcomes remain in this attempt denominator|
|Recovery share|Recovered payment count divided by initially failed payment count|
|Value comparison|(Current − previous) / previous × 100; undefined for zero previous value|
|Rate comparison|Current success percentage minus previous success percentage, in percentage points|

Payments are grouped by original initiation date, even if retries settle later. Attempt histories are observed through completion; this is a retrospective cohort analysis, not an as-of historical snapshot. Date windows include both endpoints in UTC. The previous window has the same number of days and ends the day before the current start. Partial data coverage should be interpreted carefully; absent/zero baselines display no comparison. Missing daily observations are filled with zeros by SQL.

## Findings
Insights are generated by backend SQL results: top final failure-value share, lowest market success rate (minimum 30 payments) and recovery share. They are descriptive priorities, not statistical significance tests. Market rankings are normalized by finalized payment count; raw volume and sample size remain visible.

Default 30-day window, verified on the seeded database:
- 4,395 initiated payments; 29 pending.
- €3,193,668.39 gross settled volume.
- 93.7013% final success rate.
- €197,398.00 final failed value.
- €183,083.09 recovered value.

These values are documentation snapshots. The UI requests live calculations and changes with database contents and filters.

SQL examples in `sql/analytics_queries.sql` additionally demonstrate window functions and weekly comparison. Daily charts expose fluctuations visually; the product does not claim automated statistical anomaly detection.
